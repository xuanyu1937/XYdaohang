## 三、本轮结构性决策（说明）

1. **手机页边 40 → 18 与「44px 常驻浮层」物理不可共存**：
   `18(页边) + 352(卡片) + 44(浮层) + 6(贴边) = 420 > 390`。
   二者都属本轮 P0/P2 判定项，只能放弃常驻浮层：回顶入口迁入吸顶分类条
   （`#mobileToTop`，滚超一屏点亮），视图切换迁入头部（`#mobileModeCycle`，≤480 显示）。
   浮层 DOM 保留，≤640 `display:none`，与卡片矩形零相交。
2. **组内 24 / 组间 24**：v2.18.22 判定是「组内 ≤ 组间」，本轮改为「组内不得小于组间」，
   因此 titleToFirst 由 8 提到 24，与 groupGap 相等，层级由分组卡描边区分。
3. **计数口径**：`$visibleSiteTotal` = 各分组去重后 count 之和（39），
   替代原 `$totalSites`（40）。页头「已收录 40 个站点 · 当前视图 39 个」保留两个口径，
   前者为库内收录数、后者为去重后展示数。

## 四、遗留项

1. **390 下卡片 352 / 内容列 250 已是「边距 18 + 卡片 ≥340 + 零相交」的可行上限**：
   页边再收到 16 可让卡片到 358，但 360 视口内容列会掉到 216（<220），故统一取 18。
2. **分类条溢出项为「半露」而非完整**：390 首屏可见 3 个 chip + 第 4 个半露，
   横滑可看全；不做渐隐是因为 18px 渐隐会把下一个 chip 淡成「空圆」，比截断更难理解。
3. **桌面 1440 热门条 8 项恰好排满（scrollW = clientW = 986）**，此时不显示渐隐，
   避免把末项尾部无谓淡出；若未来热门数增加触发溢出，JS 会自动补上 `is-scrollable`。
